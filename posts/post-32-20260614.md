# 如何利用Instruction File提升團隊協作效率

在我負責軟體開發專案時，通常採用高層次的管理方式，較少深入到細節。然而，當涉及到多名工程師共同維護一個服務時，使用Instruction File來定義規則，能確保大家在同一個步調下合作。這不僅提高了效率，也減少了溝通上的誤差。

Instruction File有幾種常見的使用方式。首先是repository全域的設定，可以透過單一檔案 `.github/copilot-instructions.md` 定義，適用於整個專案(https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions#creating-repository-wide-custom-instructions) 。其次是針對特定路徑的設定，例如 `.github/instructions/unit-test.instructions.md`，可以針對不同的測試類型設置專屬規則(https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions#creating-path-specific-custom-instructions) 。

這些設定可以透過公司的GitHub Copilot或其他AI agent自動生成。重要的是，我們必須確保規則被清楚定義，協作的成果不會偏離預期。為了驗證Instruction File是否被正確讀取，可以在檔案中加入`canary string`，例如：
```
<!-- canary: MYPROJECT-RULES-V1 -->
```
藉由詢問 "what is the canary?" 確認是否正常。
